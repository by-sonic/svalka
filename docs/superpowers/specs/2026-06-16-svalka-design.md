# Svalka — безопасный прозрачный чистильщик Windows

**Дата:** 2026-06-16
**Статус:** дизайн утверждён в брейнсторме, ожидает ревью спека
**Платформа:** Windows 10/11 (x64)

---

## 1. Цель

Удобный, простой, качественный аналог CCleaner, который делает две вещи лучше оригинала:

1. **Чистит ПК от реального мусора — безопасно, но явно.** Не «чёрный ящик»: пользователь видит каждый путь и его вес до удаления, и любое удаление обратимо.
2. **Удаляет программы быстро и показывает их реальные веса.** Пакетное удаление очередью + реальный размер папок на диске вместо вранья из `EstimatedSize` реестра.

Уровень — **портфолио / для себя по-взрослому**: делаем красиво и инженерно правильно, но без подписи кода, MSI-инсталлятора и защиты от чужих кривых конфигов.

## 2. Не-цели (v1)

- Нет приватности/следов (recent files, MRU, история проводника) — отложено.
- Нет очистки per-project build-артефактов (`target/`, `node_modules`, `dist/`) — только глобальные кэши пакетных менеджеров. Build-артефакты — кандидат на v2.
- Нет реестрового «оптимизатора», дефрагментации, автозагрузки, планировщика — это не v1.
- Нет кроссплатформенности — только Windows.
- Нет установщика и подписи кода.
- Нет эвристического поиска мусора по всему диску — **только явный allow-list известных путей** (см. §10).

## 3. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Аудитория | Портфолио / для себя, высокая планка качества |
| Стек | Rust + Tauri (ядро на Rust, интерфейс — вебвью) |
| Фронтенд | Svelte |
| Категории чистки v1 | Системный мусор Windows + кэши браузеров + кэши разработчика |
| Удаление программ | Глубоко: список + реальные веса + пакетное удаление + охота за остатками |
| Модель безопасности | Своя карантин-зона с откатом (файлы + реестр), авто-чистка через 30 дней |
| Раскладка UI | Боковая навигация + тонкая строка-сводка сверху раздела «Очистка» |
| Права | Админ при запуске (манифест `requireAdministrator`, UAC один раз) |
| Имя | Svalka |

## 4. Архитектура

Три слоя:

1. **Интерфейс** — Svelte в вебвью Tauri. Тонкий: рисует данные, отдаёт команды, слушает события прогресса. Никакой бизнес-логики.
2. **Ядро** — Rust. Вся логика: сканирование, подсчёт размеров, реестр, удаление, карантин. Не знает про UI, тестируется отдельно.
3. **Windows** — файловая система, реестр, Shell API (корзина), процессы.

Связь интерфейс ↔ ядро: **Tauri-команды** (запрос/ответ) + **события** для длинных операций (`scan://progress`, `quarantine://progress`).

Ключевой принцип изоляции: ядро — это отдельный Rust-крейт (`svalka-core`), который можно собрать и протестировать без Tauri. Tauri-обёртка (`svalka-app`) только мапит команды на функции ядра.

## 5. Модули ядра (`svalka-core`)

Каждый модуль — одна ответственность, чёткий интерфейс, тестируется независимо.

- **`scanner`** — находит мусор по трём группам. Вход: набор включённых категорий. Выход: дерево `Category → [CleanItem { path, size, kind }]`. Только обходит пути из allow-list (§10).
- **`sizer`** — считает реальный размер директорий. Параллельный обход (`rayon` + `walkdir`), кэш по пути. Отдаёт прогресс через колбэк.
- **`programs`** — перечисляет установленное: реестр `HKLM\...\Uninstall`, `HKCU\...\Uninstall`, `WOW6432Node`, плюс UWP/Store (через `Get-AppxPackage` или WinRT). Для каждой программы считает **реальный** размер `InstallLocation` через `sizer`, а не `EstimatedSize`.
- **`uninstaller`** — запускает `QuietUninstallString` (если есть) или `UninstallString`. Ведёт очередь для пакетного удаления нескольких программ подряд. Отдаёт статус по каждой.
- **`leftovers`** — после удаления программы ищет осиротевшие следы: папки в `Program Files`, `%LocalAppData%`, `%AppData%`, `%ProgramData%` и ключи реестра, совпадающие по имени издателя/продукта. Возвращает список **кандидатов** — ничего не трогает сам.
- **`quarantine`** — реализует безопасное удаление и откат (§7).
- **`fsafe`** — низкоуровневые операции: атомарное перемещение в пределах тома, детект занятых файлов, режим dry-run. Все удаления проходят через него.

## 6. Категории мусора v1 (конкретные пути)

**Системный мусор:**
- `%TEMP%` и `C:\Windows\Temp`
- Корзина: содержимое тоже уезжает в карантин, как и всё остальное (перемещение в пределах тома — мгновенно), поэтому даже «очистка корзины» обратима 30 дней. Перечисление — через Shell API.
- Кэш миниатюр: `%LocalAppData%\Microsoft\Windows\Explorer\thumbcache_*.db`, `iconcache_*.db`
- Дампы падений: `C:\Windows\Minidump`, `%LocalAppData%\CrashDumps`, `*.dmp`
- Windows Error Reporting: `%ProgramData%\Microsoft\Windows\WER`, `%LocalAppData%\Microsoft\Windows\WER`
- Остатки Windows Update: `C:\Windows\SoftwareDistribution\Download` (помечается как «требует осторожности»)

**Кэши браузеров** (Chromium: Chrome, Edge, Brave и др.; Firefox):
- `...\User Data\<Profile>\Cache`, `Code Cache`, `GPUCache`
- Firefox: `...\Profiles\<p>\cache2`
- **НЕ трогаем:** `Cookies`, `Login Data`, `Web Data`, `History`, `Bookmarks` — чтобы не разлогинивать и не терять данные.

**Кэши разработчика** (только если найдены; всё регенерируемо):
- Cargo: `%USERPROFILE%\.cargo\registry\cache`, `registry\src`
- npm: кэш из `npm config get cache`
- pip: `%LocalAppData%\pip\Cache`
- Gradle: `%USERPROFILE%\.gradle\caches`
- Go: `%LocalAppData%\go-build`, `%USERPROFILE%\go\pkg\mod`
- Yarn: `%LocalAppData%\Yarn\Cache`

## 7. Карантин и откат (главная фича безопасности)

**Удаление = перемещение, не стирание.**

- На каждом томе заводится склад: `X:\.svalka-quarantine\<entry-id>\`. Перемещение в пределах тома — это атомарный rename: мгновенно и без лишнего места, поэтому **десятки ГБ dev-кэшей уезжают в карантин за секунду**. (Штатная Корзина на таких объёмах захлебнулась бы из-за лимита размера — поэтому её не используем для мусора.)
- **Ключи реестра** перед удалением экспортируются в `.reg` и кладутся в папку записи карантина.
- **Центральный манифест** в `%LocalAppData%\Svalka\quarantine.json` помнит для каждой записи: оригинальные пути, тип (файл/реестр), время, источник (какая операция), суммарный вес.
- Раздел «Карантин» в UI: список записей → **Восстановить** (вернуть файлы на место, импортировать `.reg`) или **Удалить навсегда**.
- **Авто-чистка**: записи старше **30 дней** (настраивается) удаляются навсегда при старте приложения.

Round-trip — это контракт: всё, что попало в карантин, должно восстанавливаться побайтово в исходное место.

## 8. Прозрачность — поток «явно»

1. **Скан** (раздел «Очистка»): тонкая строка-сводка сверху («Найдено 4.2 ГБ»), ниже категории с галочками и весами.
2. **Раскрытие**: любую категорию можно развернуть до **конкретных путей с весами**. Пользователь видит ровно то, что уйдёт.
3. **Снятие галочек** с того, что не трогать — на уровне категории или отдельного пути.
4. **«Отправить в карантин»** — только после того, как список показан. Никаких действий вслепую.

Тот же принцип в удалении программ: остатки показываются списком кандидатов, пользователь галочками решает, что снести; ничего не удаляется без явного подтверждения.

## 9. Скорость и подсчёт размеров

- Сканирование и подсчёт — **фоновые**, с живым прогрессом через события Tauri. Интерфейс не морозится.
- Обход директорий параллельный (`rayon`).
- Результаты размеров кэшируются, чтобы повторный заход в раздел был мгновенным.

## 10. Безопасность: что НИКОГДА не трогаем

Принцип v1: **allow-list, а не эвристика.** Сканер обходит только жёстко заданные известные пути. Он не «угадывает» мусор по всему диску.

Явный deny (даже если случайно попадёт в обход):
- Браузер: `Cookies`, `Login Data` (пароли), `Web Data`, `History`, `Bookmarks`.
- Система: `C:\Windows\System32`, `WinSxS` (хранилище компонентов), `hiberfil.sys`, `pagefile.sys`, `swapfile.sys`.
- Пользовательские папки: `Documents`, `Desktop`, `Downloads`, `Pictures`, `Videos` и прочее личное.

Единственная эвристическая часть — поиск остатков после удаления программ (`leftovers`). Именно поэтому она спрятана за поэлементное подтверждение галочками и проходит через карантин (обратима).

## 11. Обработка ошибок

- **Никаких тихих сбоев.** Занятый файл (открыт браузер и т.п.) не глотается молча: пропускаем и явно показываем «не удалось: занят процессом» с именем процесса.
- Каждый неудачный элемент операции виден пользователю с причиной.
- Операции идемпотентны и устойчивы к частичному выполнению: упали на середине — манифест карантина консистентен, уже перемещённое восстановимо.

## 12. Тестирование

- Ядро (`svalka-core`) тестируется без UI.
- `scanner`/`sizer`/`fsafe` — на временных директориях (`tempfile`).
- `programs`/`leftovers` — на поддельном реестре (изолированный тестовый корень в `HKCU`).
- **Round-trip карантина** — главный тест: создали файл/ключ → в карантин → восстановили → побайтово совпало.
- Режим **dry-run** во `fsafe` — операции логируются, но не выполняются; используется в тестах и как «пробный прогон» в UI.

## 13. Структура репозитория (предварительно)

```
Svalka/
  Cargo.toml                 # workspace
  crates/
    svalka-core/             # ядро, без Tauri
      src/{scanner,sizer,programs,uninstaller,leftovers,quarantine,fsafe}.rs
      tests/
    svalka-app/              # Tauri-обёртка
      src/                   # команды + события
      tauri.conf.json        # requireAdministrator в манифесте
  ui/                        # Svelte (Очистка / Программы / Карантин / Настройки)
  docs/superpowers/specs/
```

## 14. Технологии

- `tauri` (v2) — оболочка и IPC.
- `winreg` — реестр.
- `windows` (windows-rs) — Shell API (корзина), процессы, манифест.
- `walkdir` + `rayon` — параллельный обход и подсчёт.
- `serde` / `serde_json` — манифест карантина, IPC-модели.
- Svelte + Vite — фронтенд.
